# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Shopify Online Store 2.0 theme: **Craft v16.1.0** (see `config/settings_schema.json`), a Dawn-derived theme. `AGENTS.md` is titled "Dawn theme instructions" and the JS comments still say "Dawn", but the theme is Craft. There is no build step, no `package.json` and no README. The code lives in the private GitHub repo `samanhoseinpour/pegasus-pens` (remote `origin`, default branch `main`).

Rules from `AGENTS.md`: follow OS 2.0 conventions; preserve existing section setting IDs and merchant configuration; prefer small reusable snippets over duplicated Liquid; keep changes theme-editor compatible.

The store is **Pegasus Pens**. The visual identity is a design layer on top of Craft (see "Pegasus design layer" below), inspired by the Wonder/"NOOK" reference in `docs/wonder-reference-discovery.md`. No Wonder code, imagery or icons are used.

## Pegasus design layer

Craft stays the engine. The identity comes from settings plus a few files loaded after Craft's. The brand is the emblem in `docs/brand/` (gold and bronze on parchment, espresso lettering, one maple-leaf red); `docs/brand/README.md` has the palette, the contrast rule and the photo inventory.

- **Palette lives in the color schemes** (`config/settings_data.json`, `scheme-1..5`): Parchment `#F6ECD8` / Sand `#E9CDA9` / Bronze `#7D5027` / Espresso `#22110A` (gold buttons) / Maple `#8E221C`; text ink `#2A1508`. Change surfaces there. `assets/pegasus.css` `:root` holds the brand constants (`--pg-gold`, `--pg-espresso-rgb`, ...), and no section CSS may hardcode a color. **Gold is for dark surfaces only**: on parchment it is 1.9:1.
- `assets/pegasus.css` (loaded right after `base.css`): tokens, type scale, buttons, announcement bar, wordmark, footer wordmark, reveal classes. It uses Craft's `--font-*` and `--color-*` variables, never the font names directly, so turning the font setting off falls back cleanly. Focus rings use `rgb(var(--color-foreground))` so they work on every scheme.
- `assets/pegasus.js`: ink-wipe on large images, word-rise on headlines, `data-scrolled` on `<html>`. It does nothing under reduced motion, in the theme editor, or when `settings.pegasus_motion` is off. New sections opt in with `data-pg-wipe` / `data-pg-rise`; `window.Pegasus.init(scope)` re-runs it after a section re-render. **The clip-path of a wipe goes on the element's children, never on the observed element**: the browser counts an element's own clip-path when judging visibility, so a fully clipped target is never revealed (this once left every wipe image blank). A reveal also waits for the images inside to load (capped at 2.5 s) and switches lazy ones to eager first, because a fully clipped image never counts as near the viewport and would not start loading; without that the wipe played over an empty box on slow connections.
- `snippets/pegasus-wordmark.liquid`: `assets/pegasus-emblem.png` plus the shop name (first word upright, rest italic). Used by the header (when no logo image is set) and the footer; the emblem is also the favicon fallback. The wordmark shrinks at 749, 389 and 339 px so the header never overflows; below 340 px the text becomes screen-reader-only.
- `snippets/pegasus-scene.liquid` + `assets/pegasus-scene-*.jpg`: bundled lifestyle photos used as default images (hero medallion, story section, collage tiles) until the merchant chooses their own. Product shots are not bundled; they belong to the products.
- Cards: Craft's "portrait" ratio is changed from 4:5 to **3:4** in `card-product` and `card-collection`, because the photographs are 3:4 (4:5 crops the pen clips).
- Card extras (in `snippets/card-product.liquid`, both badge blocks: the visible one for the standard card style is the first, inside `card__inner`): product tags `limited` and `new-run` show a "Limited" (espresso) or "New run" (bronze) badge, after sold out and sale, which win (no pen carries those tags now: every pen is one of a kind). `snippets/pegasus-swatch-dots.liquid` shows up to five dots from the first option whose values have **swatches** (set in the Shopify admin), and nothing otherwise. The extra photos on a card are the existing `show_secondary_image` setting (now on for the collection page), see "Collection pages". Quick add is deliberately left off: it would bypass the engraving and gift options on the product page. New storefront keys must also be added to every `locales/*.json` (English text), or theme-check fails `MatchingTranslations`.
- Settings added: `pegasus_fonts` (self-hosted Newsreader + Hanken Grotesk, OFL, licenses in `docs/font-licenses.md`; overrides the font pickers) and `pegasus_motion`; footer `show_wordmark`. New schema labels in *theme settings* must be added to **every** `locales/*.schema.json` (theme-check fails `MatchingTranslations` otherwise); section-schema labels for the Pegasus sections are plain English.
- Craft's own `animations_reveal_on_scroll` is off in the saved settings because `pegasus.js` replaces it.
- Typography rules: sentence case for labels (no all-caps eyebrows), UI text tracking reset to `0.01em` (Craft tracks much wider), display headings use `font-optical-sizing: auto`.

The store is `rjxgij-f1.myshopify.com` (public since 2026-11-07, CAD, ships to Canada). Test on it, not on a mock: while `shopify theme dev --store rjxgij-f1.myshopify.com` runs, http://127.0.0.1:9292 serves the local files on Shopify's engine with the real store data and no password prompt, so Playwright can drive it (WebKit too, the owner browses in Safari; give lazy photos a few seconds, the proxy is slow). The CDN's `standard-events.js` fails CORS from localhost, so tests stub it. Earlier checks used a throwaway LiquidJS renderer with a mock catalog; it hid engine differences (see "Liquid trap") and features only a real store has: Follow on Shop (off in the footer), Shop Pay installments, the Buy with Shop button, "Powered by Shopify".

**The catalog is the client's.** Their folder `product-images/` (gitignored: one folder per pen with photos and a Word doc, plus `Pegasus about us.docx`) was applied on 2026-11-13 through the Admin API with a scratch script: eight one-of-a-kind pens with the docs' names, descriptions and CAD prices, each stocked at 1 with overselling denied, all tagged `gift`. Product types are also automatic collections whose handle is the handleized type (the breadcrumbs rely on that): `Hardwood` (cross-grain oak, maple, olive, plum wood and Persian Khatam), `Segmented wood` (six hardwoods; walnut, rosewood, maple and pink acrylic), `Leather`, `Date seed`; `gifts` is the tag collection (all eight). Every photo has a descriptive file name (`<handle>-<view>.<ext>`) and its own alt text (rule and full list in `docs/brand/README.md`); the first photo of every pen is a white studio shot, which the spotlight, the drifting pens and the cards rely on. The five earlier placeholders were these real pens: they kept their IDs and their old handles redirect. The sixth (`rose-resin-pen`, not one of the client's pens) is a draft. Pages: `about`, `contact`, `shipping-returns` (still "coming soon"), `care`; menus `main-menu` and `footer`.

## Home page

`templates/index.json` order: `pegasus-slider` (id `hero`) → `pegasus-scrub` (statement) → `collection-list` (four materials) → `pegasus-product-tabs` → `pegasus-spotlight` → `pegasus-constellation` → `image-with-text` (story) → `pegasus-collage` → `pegasus-parallax` → `pegasus-engrave` → `gifts` (a second product shelf) → `pegasus-photo-cards` → `pegasus-marquee` (dark) → `pegasus-review-wall` (id `quotes`) → `pegasus-pills` → `pegasus-features` (promises). The announcement bar, header and footer come from the section groups (the newsletter lives inside the footer).

New sections (all with presets, so merchants can add them anywhere; schema labels are plain English, not `t:` keys, so no locale files are needed for them):

- `pegasus-hero`: espresso hero. The photo (or a bundled scene) sits in a circular **medallion** with a double gold rim, echoing the emblem; the rim draws itself and the circle opens on load. `image_style: background` gives a full-width photo (with a star-field fallback), and `show_constellation` draws the Great Square (off by default). The headline is split into `.pg-w/.pg-wi` word spans in Liquid and animated with CSS keyframes only, so there is no flash and no JS dependency.
- `pegasus-slider` (the home hero; `pegasus-hero` is still available as a single-slide section): up to five slides, each rendered by `snippets/pegasus-hero-slide.liquid` (the hero's markup, shared with `pegasus-hero`). `<pg-slider>` (assets/pegasus-slider.js) stacks the slides in one grid cell and crossfades them; inactive slides are `visibility:hidden` and `inert`. Each slide is the medallion style or the full-width style (its own photo, or a bundled `background_scene`, with a slow drift). Every animation inside an inactive slide is switched off (`animation: none !important`) so its entrance (rising words, medallion, rim) replays each time it becomes active. Autoplay is the **progress line of the active dot** (a CSS animation); its `animationend` moves to the next slide, so `animation-play-state: paused` pauses the timing too. It holds for the pointer, *keyboard* focus (`:focus-visible` only, so a mouse click does not stop it for good), a hidden tab and being off screen. The bar under the slides holds only the dots (the owner removed the arrows and the pause button; swiping still works on touch), which means there is no explicit pause control: WCAG 2.2.2 asks for one on content that moves by itself for more than 5 seconds, so the `autoplay` setting is the way to turn it off. No autoplay and no transition under reduced motion, in the theme editor, or with motion off; selecting a slide in the editor shows it. `render` tags in Liquid take values, not expressions (`lazy: forloop.first == false` fails theme-check), so the flag is assigned first.
- `pegasus-spotlight` (featured pen): one product as a cutout (white photo background removed with `mix-blend-mode: multiply` on the pen wrapper, light color scheme only) inside a double bronze rim that echoes the emblem, with its name, description, three detail blocks, an automatic **ink row built from the product's first option** (names plus colour dots, the dots `decorative` so screen readers do not hear the names twice), price, a "View pen" button and an "Engrave it" link to `<product>?engrave=` (hidden by its empty label on the home page while engraving is off). An empty `?engrave=` makes `pegasus-personalize.js` open the engraving panel and put the cursor in the field (a non-empty one also pre-fills it). The entrance (pen rises and straightens, rim grows) is CSS scroll-driven animation (`animation-timeline: view()`) behind `@supports`, so unsupported browsers and reduced motion just show it settled. The rim is an empty div, so it needs `.pg-spot__stage > .pg-spot__ring { display: block }` to beat Craft's `div:empty { display: none }`.
- `pegasus-features` (the promises row, id `promises`) and `snippets/pegasus-icon.liquid`: five hand-drawn line icons (engraving plate, refill cartridge, gift box, envelope, mountains; 48 px grid, `currentColor`, every path has `pathLength="1"` so it can be drawn with `stroke-dasharray: 1`). Each feature is an icon, a title and a line, with a hairline above; four across from 990 px, two on tablets, one on phones. The icons draw themselves as the row scrolls in with CSS scroll-driven animation behind `@supports`; elsewhere and with reduced motion they are just drawn. Copy states what exists, no prices or conditions. Add icons by adding a `when` in the snippet and an option in the block's `icon` setting.
- `gifts` (id) is a second `pegasus-product-tabs` shelf ("Ready to give"); its tabs are Gift pens, Leather and Date seed.
- `pegasus-review-wall` (id `quotes`; `pegasus-quotes`, the one-quote-at-a-time rail, is still available): a slow loop of review cards. Two identical tracks sit side by side and each slides left by its own width (`translateX(-100%)`), so the loop has no seam; the Liquid repeats the card set inside each track until a track is wider than any screen (about 24 000 px of cards), the copy track and the repeats are `aria-hidden`, and only the real blocks are exposed. The duration is *seconds per card* times the cards in a track, so the speed stays the same whatever the number of reviews. It pauses under the pointer and when the wall (a focusable, named region) has keyboard focus. Reduced motion: no animation, the copy track is hidden and the wall scrolls by hand. Stars (`rating` 0 to 5, 0 hides) must only show ratings customers really gave. **The three reviews on the home page are still my placeholders (Maya R., Tomás A., Priya S.)**: the client sent none, and the owner chose on 2026-11-13 to keep them for now. Replace them with real ones.
- Pinned lengths: the constellation's `scroll_length` setting (default 360%, was a fixed 480) and the parallax's `length` (default 240%, was 320) keep the pinned scroll to about a third of the page instead of 43%.
- `pegasus-parallax` ("Hand-turned, one at a time."): NOOK's pinned giant headline with objects drifting past, done with pens. `<pg-parallax>` pins the stage (`position: sticky`, section height = `length` setting in vh) and writes the scroll progress through the section to `--p` (0 to 1). Everything else is CSS: each pen block gets a window of the scroll (`--start`, `--span`, computed in Liquid; overlapping), `--q` runs 0 to 1 inside it, and the pen's position and rotation are `calc()` of `--q`. Pens are decorative (`aria-hidden`, `pointer-events: none`). **The white photo backgrounds are removed with `mix-blend-mode: multiply` on the pen (`li`), and the stage carries the section color itself**: a sticky, isolated or transformed element is its own stacking context, so a blend on the image or without a background on the stage leaves white rectangles. Use a light color scheme. Without motion it never pins and the pens sit in a row under the headline.
- `pegasus-scrub` (the home statement): the text is split into word spans in Liquid (the words stay in the accessibility tree as ordinary text: `aria-label` is not allowed on a paragraph, and hiding every word left screen readers nothing to read); `<pg-scrub>` writes `--p` and each word's opacity is `clamp(0.14, calc((p * (n + 3) - i) / 3), 1)`, so a soft wave of light passes down the text as it scrolls through the screen, and reverses on the way back. Every word is fully visible without the script or with reduced motion.
- `pegasus-product-tabs`: `<pg-tabs>` (assets/pegasus-tabs.js) over `<pg-rail>` carousels (assets/pegasus-rail.js). Tab blocks pick a collection; empty collections show placeholder cards.
- `pegasus-constellation`: the signature pinned section, `<pg-constellation>` (assets/pegasus-constellation.js). Scroll progress drives `--seg-1..6` (line drawing), `.is-lit` / `.is-active` on stars and `.is-active` on panels. It pins **only** when motion is allowed (not reduced-motion, not theme editor, not `pegasus_motion` off); otherwise it renders statically with all four panels visible. It also does not pin when the window is shorter than 620 px (a phone on its side, a small window): the pinned stage is at least 52rem tall, so its lower part, with the star buttons, would sit below the fold with no way to scroll to it. `setPinned()` switches on a `(max-height: 619px)` media query and, when unpinning, clears `--seg-*`, `.is-lit` and `.is-active` so the static layout is complete (and `render()` returns early when unpinned, because a frame queued by the resize can arrive after the switch). Inactive panels use `visibility: hidden`, and the nav buttons jump to a star by scrolling.
- `pegasus-marquee`: slow looping text (the only continuous motion); two copies of the list, the second `aria-hidden`; stops under reduced motion.
- `pegasus-quotes`: one big quote at a time in a `<pg-rail>`; the track is focusable and named via a setting.
- `pegasus-collage`: 12-column composition (tall tile, wide tile, two small; stacks on phones; `max_blocks: 4`). Blocks are `tile` (image, title, link) or `product` (title, price and image come from the product). Each tile is one `<a>`. A `product` tile is a clean card (photo on white, caption beneath, nothing over the pen). Tiles with no image use a `scene` photo, or their color scheme plus a CSS star field that follows `--color-foreground`, so it reads on dark and light schemes. `caption_style: dark` swaps the dark scrim for a paper fade, for light product shots.
- `pegasus-engrave`: a full-width espresso **plate** that shows what the visitor types, character by character (`<pg-engrave>`, assets/pegasus-engrave.js). The first time it is 60% in view it types the sample text once as a demo (not under reduced motion, in the theme editor, or with motion off); after that the plate is user-driven, and an empty field shows the sample faintly. Each new character is appended alone (earlier ones are never re-rendered, so their animation is not restarted) and is added as a text node, never as markup. The button is a plain GET `<form>` to the chosen product (`?engrave=<text>`), so it works without JS, and `pegasus-personalize.js` reads `?engrave=` on the product page to open the engraving panel pre-filled. Its character limit is its own setting and should match the product block's. **Disabled on the home page since 2026-11-13**: the client's documents never mention engraving, so it stays off until the client confirms it.
- `pegasus-pills`: "Where would you like to start?" quick links as large italic serif outlines that fill on hover (blocks: label + link, max 10). On the home page they are the four material collections, Gifts and All pens.
- `pegasus-photo-cards`: "Inside a Pegasus pen": a full-bleed photo (image setting, or a bundled `pegasus-scene`; `focus` picks which band of a tall photo stays in view) under a dim layer, with up to four frosted cards (`backdrop-filter`, ink text set explicitly because the scheme's heading color would be cream on parchment). Cards stagger upward on wide screens only. It is not a sequence, so no numbering. Copy sticks to facts already on the product pages (turned barrel, twist action, refillable cartridge).
- Shared snippets: `pegasus-constellation` (the Great Square SVG, stars 1-4 are the square, 5-6 trail off) and `pegasus-rail-controls` (progress line + prev/next).

`<pg-rail>` cancels native `dragstart` (links and images otherwise swallow the pointer events and break drag-to-scroll) and snaps explicitly after a drag.

## Smooth scrolling (Lenis)

`assets/lenis.min.js` (self-hosted, MIT, notice in `docs/third-party.md`) plus `assets/pegasus-smooth.js`, loaded after `pegasus.js` only when the theme settings `pegasus_smooth_scroll` and `pegasus_motion` are both on (`<html data-pg-smooth>` mirrors it). It eases the **mouse wheel** only: touch scrolling stays native (`syncTouch` off), keyboard scrolling and anchors are untouched (`anchors: false`, because Lenis would `preventDefault` the skip link and lose its focus move). It never starts for visitors who prefer reduced motion or in the theme editor, and it is destroyed if reduced motion is turned on later.

- Lenis scrolls the real window (`scrollTo` each frame), so scroll listeners, `position: sticky`, IntersectionObserver and CSS scroll-driven animations all keep working; nothing else in the theme knows about it.
- **Page locks:** Craft locks the page by styling `<body>` overflow (`overflow-hidden`, `-mobile`, ...) while a drawer, modal or menu is open. A MutationObserver reads the *computed* body overflow (so Craft's media queries apply) and calls `lenis.stop()`/`start()`. Without it the page would scroll behind an open drawer.
- **Inner scrollers:** the `prevent` option returns true for any element in the wheel's path that scrolls vertically by itself (`overflow-y: auto|scroll` and taller than its box), so drawers, the search results and long lists scroll natively. Horizontal rails are unaffected (no vertical overflow).
- **Programmatic scrolling:** call `window.Pegasus.lenis.scrollTo(...)` when it exists. The back-to-top button does; a native `behavior: 'smooth'` would fight Lenis's easing. Tests that count native wheel steps (`ixheader`) destroy it first with `window.Pegasus.lenis.destroy()`.
- CSS for it ("Lenis smooth scroll") is at the end of `pegasus.css`.

## Contact page

`templates/page.contact.json` uses one section, `sections/pegasus-contact.liquid` (+ `assets/pegasus-contact.css`, `assets/pegasus-contact.js`), instead of Craft's `main-page` + `contact-form`. It is Shopify's own contact form (`{% form 'contact' %}`, posts to `/contact`), so spam protection, the email to the store and the success redirect are Shopify's.

- **The plate:** the dark engraving plate from the home page returns as the form's header. `<pg-contact>` engraves the chosen **topic** on it (characters cut in one after another, staggered with `--i`; text added as text nodes), shows that topic's hint line (`aria-live="polite"`, also the textarea's `aria-describedby`) and relabels the "pen or order" field. After a successful send the plate engraves `success_plate` and the form is replaced by a confirmation whose heading takes focus. Topics are **blocks** (label, hint, label for the pen/order field), so the merchant edits them in the theme editor.
- **Radios:** topics are real radios in a `<fieldset>`; the chip is the label, the (transparent) input covers it. In tests click the input, not the label (the input intercepts the pointer). `?topic=a gift` preselects a topic by its text, so another page can link to `/pages/contact?topic=engraving`.

- **Field names** are Shopify's: `contact[name]`, `contact[email]`, `contact[body]`, plus `contact[Topic]` and `contact[Pen or order]`, which arrive in the message as extra lines (their names are settings). No phone field, on purpose.
- **Errors:** an `role="alert"` summary (focused) links to the field; the email input gets `aria-invalid` and `aria-describedby`. Shopify gives back `form.name`, `form.email` and `form.body` after an error but not custom fields, so the chosen topic is not restored.
- **No invented facts:** no phone, address, hours or reply time. The only facts are the ones already on the site ("Hand-turned in British Columbia, Canada") and the store's own `shop.email`. The announcement bar's "Contact us" link (`shopify://pages/contact`) opens this page, so a page with the handle `contact` and the template suffix `contact` must exist in the Shopify admin.
- Preview harness: `/pages/contact` renders it; `?state=success` and `?state=error` simulate Shopify's two outcomes, and a POST to `/contact` redirects to them (harness only, not in the repo).

## Commands

Everything goes through Shopify CLI (5.0.0 installed). There is no `shopify.theme.toml`, so pass `--store` yourself.

- Lint: `shopify theme check --path .` (`--fail-level error`, `-a` to auto-correct, `-j` for JSON)
- Preview / sync: `shopify theme dev --store <shop>.myshopify.com`, `shopify theme pull|push` (need store auth)
- Deploy: pushes to `main` are meant to update the Shopify theme through Shopify's GitHub integration (connected once in the Shopify admin: Online Store > Themes > Add theme > Connect from GitHub). That integration is two-way: edits made in the theme editor are committed back to the branch, so `git pull` before you push, and expect `config/settings_data.json` and `templates/*.json` to change under you.
- Commits carry **no `Co-Authored-By` trailer and no mention of Claude** (the owner asked for this; GitHub otherwise lists "claude" as a co-author). Do not add attribution lines to commit messages or PR bodies.
- There is no test suite.

Lint is **clean** (0 errors, 0 warnings): keep it that way. Two inline suppressions are deliberate: `applicable_disclosures` in `snippets/cart-disclosure-indicator.liquid` and `snippets/product-disclosures.liquid` (a Shopify filter newer than the bundled theme-check) and `offset: continue` in `sections/main-product.liquid` (valid Liquid that the checker reads as an unknown object). `snippets/facets-footer.liquid` is the tail of the facets bar (sort form, product count, filter pills), split out of `facets.liquid` to stay under the LiquidComplexity limit of 120.

**Liquid trap: no `}` inside a `{{ }}` output.** Shopify's Liquid ends an output tag at the first `}`, so `{{ x | default: '{count} of {max}' }}` is a syntax error there, while theme-check and LiquidJS accept it. Shopify's GitHub import then **silently drops the file** (this once removed `pegasus-engrave` and the personalize snippet, and with them `main-product`, `index.json` and `product.json`, and Shopify committed an empty `index.json` back to the repo). Put such strings in `{% liquid assign ... %}` first (inside a `{% %}` tag braces are fine) and output the variable. Braces inside `{% schema %}` JSON are fine. After the import, check Edit code in the Shopify admin: every file in the repo should be listed.

**Liquid trap: a whitespace-only block body outputs nothing.** Shopify's Liquid removes the text from an `if`, `unless`, `case` or `for` when every branch is only whitespace, so `{% unless forloop.last %} {% endunless %}` prints no space, while LiquidJS keeps it. This once ran every word of the home hero and statement together ("Turnedfromasingleblank."), and neither theme-check nor the LiquidJS preview showed it. To output a space use `{{ ' ' }}`, and test Liquid whitespace on the real engine (the `liquid` Ruby gem), not on LiquidJS.

**Schema names are limited to 25 characters** (section, block and preset names, after `t:` keys are resolved). Shopify's GitHub import silently drops a section whose block name is longer, and theme-check does not warn: `Engraving and gift options` (26) once kept `main-product`, and with it `product.json`, off the store. Craft's own names all fit. **A template that uses a block type more often than the block's `limit` is dropped the same way**, and theme-check does not see it either: Craft's Image with text takes one `text` block, and a second one (2026-11-13) kept the new About template off the store while every other file imported. To see Shopify's real error, push the one file to a throwaway development theme: `shopify theme push --store <shop> --theme <dev theme id> --only <file> --nodelete`.

## Architecture

**Standard OS 2.0 layout.** `templates/*.json` list sections; `sections/header-group.json` and `footer-group.json` are section groups rendered by `layout/theme.liquid` via `{% sections %}`. `templates/gift_card.liquid` is the only Liquid template, and `layout/password.liquid` is the alternate layout.

**Auto-generated JSON is not valid JSON.** `config/settings_data.json`, `templates/*.json` and `sections/*-group.json` start with a `/* ... */` warning comment, so `json.load` fails on them. The theme editor rewrites these files, so hand edits can be overwritten. Keep setting IDs and block IDs stable: they are the merchant's saved configuration. `settings_data.json` currently has `cart_type: "notification"`, so the cart-drawer code path is inactive in the shipped config.

**No bundler; shared global scope.** `assets/*.js` are plain scripts loaded with `defer`. They share globals (`PUB_SUB_EVENTS`, `publish`/`subscribe`, `fetchConfig`, `debounce`, `routes`, ...), so order matters: `constants.js` → `pubsub.js` → `global.js` in `theme.liquid`. `theme.liquid` loads only `base.css`, a few cart stylesheets and the global JS; each section or snippet loads its own `component-*.css`/`*.js` itself (`{{ 'x.css' | asset_url | stylesheet_tag }}`). A new section must load its own assets. `card-product` has a `skip_styles` param to avoid loading CSS twice. Some loads in `theme.liquid` are conditional on settings (`cart_type == 'drawer'`, `predictive_search_enabled`, `animations_reveal_on_scroll`, localization).

**Behavior lives in custom elements.** Liquid emits a tag (`<product-info>`, `<cart-items>`, `<variant-selects>`, ...) and the matching `customElements.define` is in `assets/`. Components coordinate through the pubsub bus in `pubsub.js`, with event names in `constants.js` (`cart-update`, `variant-change`, ...).

**Server-rendered partial updates (Section Rendering API).** JS fetches `?section_id=<id>` or `sections=` and swaps in HTML. The schema-less sections (`cart-drawer`, `cart-icon-bubble`, `cart-notification-*`, `cart-live-region-text`, `pickup-availability`, `predictive-search`) are fragment renderers only. Their section IDs and DOM selectors are hard-coded in each element's `getSectionsToRender()` (`cart.js`, `cart-drawer.js`, `cart-notification.js`) and in JS fetches. Renaming a section, ID or selector breaks the JS without any lint error.

**`standard-actions-override.js`** bridges Shopify's Standard Actions bundle (`Shopify.actions.updateCart`/`openCart`) to the pubsub bus. It hard-codes the cart element tags (`DAWN_CART_TAGS`) and which sections the pubsub subscribers already refresh (`DAWN_PUBSUB_REFRESHED_SECTIONS`). Update both if you add or rename a cart element or section.

**External CDN dependency.** `theme.liquid` imports `https://cdn.shopify.com/storefront/standard-events.js` as a module, sets `window.StandardEvents`, and defines `collection-component` and `product-component`. `cart.js` does `class CartItems extends window.StandardEvents.createViewEventElement(...)` with no fallback, so cart code throws if that module fails to load. Other call sites guard with `window.StandardEvents || {}`.

**Theme-editor compatibility.** Per-section styles use `{%- style -%}` scoped by `section.id`. `theme-editor.js` (loaded only by the slideshow, main-product, featured-product and announcement-bar sections) handles `shopify:section:*` and `shopify:block:*` events. Any JS that holds state across a section re-render needs the same treatment.

**Snippets.** Public params are documented in `{% doc %}` blocks (24 of 39 snippets so far; sections have none). Match that format when adding or changing a snippet's params.

**i18n.** All visible strings go through `t:` keys. `locales/en.default.json` holds storefront strings and `en.default.schema.json` holds theme-editor labels. Add new keys to both English defaults; other locales fall back. Strings needed by JS are not read from locale files directly. `theme.liquid` injects them as `window.cartStrings`, `window.variantStrings`, `window.quickOrderListStrings` and `window.accessibilityStrings`, so add new JS-facing strings there.
